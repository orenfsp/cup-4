# Идея проекта

## «Отклик»

«Отклик» — безопасная платформа для обращений школьников, родителей и педагогов за помощью.

Пользователь может спокойно описать ситуацию, получить секретный код обращения и продолжить диалог без регистрации и публикации личных данных. Оператор распределяет обращение, а специалист помогает в отдельном рабочем интерфейсе. При необходимости обращение можно вернуть оператору и передать другому специалисту.

## Зачем это нужно

В чувствительных ситуациях человеку важно получить помощь без лишних барьеров, публичности и необходимости сразу раскрывать контакты. Платформа объединяет простой вход, бережный интерфейс и ролевое разграничение доступа.

## Основные принципы

- минимум собираемых данных;
- доступ к обращению только у тех сотрудников, которым он необходим;
- секретный код вместо обязательной регистрации заявителя;
- понятные статусы и возможность продолжить обращение позже;
- русский mobile-first интерфейс;
- кризисные сигналы и вложения обрабатываются с отдельными ограничениями безопасности.

# План развития

## Ближайший MVP

1. Запуск приложения одной командой через Docker Compose.
2. Подача обращения от лица школьника, родителя или педагога.
3. Выдача секретного кода и возврат к обращению по этому коду.
4. Рабочие кабинеты оператора и специалиста.
5. Назначение обращения и защищённый диалог.
6. Ответ специалиста, возврат оператору и переназначение.
7. Подтверждение результата и оценка помощи.

## Следующие этапы

- кризисные признаки и согласованные контакты помощи;
- безопасная работа с изображениями-вложениями;
- совместная работа нескольких специалистов и временная блокировка действий;
- автоматическое закрытие неактивных обращений по правилам;
- управление сотрудниками, настройками маршрутизации и нагрузкой;
- аналитика и экспорт обезличенных данных;
- подготовка production-развёртывания: HTTPS, мониторинг, резервное копирование и аудит.

## Критерии готовности

Каждый этап принимается по реальному пользовательскому сценарию, проверкам прав доступа, обработке ошибок и отсутствию приватных данных в логах. Новые функции не должны открывать текст обращения ролям, которым он не предназначен.

# Технологический стек

## Приложение

- **Backend:** Python 3.12, Django 5.2 LTS, Django ORM и миграции.
- **Frontend:** React 19, TypeScript, Vite.
- **База данных:** PostgreSQL 17.
- **Веб-сервер:** Nginx как reverse proxy и сервер статических файлов.
- **Запуск:** Docker Compose.

## Архитектурные решения

Frontend обращается к единому Django API. Данные хранятся в PostgreSQL, приватные вложения — во внутреннем Docker volume и не публикуются напрямую. Секреты передаются контейнерам через отдельный secrets volume. Проверка роли и доступа выполняется на сервере для каждого объекта и маршрута.
